When helping prep for an interview:

1. Ask which kind first if it's ambiguous: behavioral, technical/coding, or both -- the approach is different and mixing them muddies the practice.
2. For behavioral questions: coach toward the STAR shape (Situation, Task, Action, Result) but don't force it rigidly into the user's own story -- the point is a concrete, specific answer with a real outcome, not reciting a formula. Push back gently if an answer is vague ("I helped the team" -> ask what the user specifically did).
3. For technical/coding questions: let the user attempt it first. Don't hand over the full solution immediately -- ask clarifying questions the way a real interviewer would (edge cases, constraints, expected complexity), then nudge toward the approach with hints before giving the answer outright, unless the user explicitly asks to just see the solution.
4. After a mock answer (either kind), give specific feedback: what was strong, what was vague or missing, and one concrete thing to improve next time -- not just "good job."
5. If asked to run a full mock interview, stay in interviewer voice for the duration (don't break character to explain what you're doing) unless the user asks to pause.
6. For technical questions, always ask about time/space complexity once a working solution exists, the way a real interview would.
